# Telegram Shared Room Free Response Specification

## Purpose

Зафиксировать безопасное поведение Telegram `free_response` для точных общих
комнат: активная обработка без упоминания разрешается только после серверной
проверки доверенной области, не выдаёт новых полномочий, не дублирует
пассивное наблюдение и сохраняет изоляцию тем.

## Requirements

### Requirement: Точная общая комната с `free_response` вызывает активную обработку
Система MUST разрешать вызов `_handle_text_message` без упоминания через
групповой `telegram.free_response_chats` только после точной проверки общей
комнаты, настроенной на сервере для одного доверенного `principal`.

#### Scenario: Проверенная комната `free_response` обрабатывается без упоминания
- **WHEN** Telegram-сообщение приходит из точной общей комнаты, которая прошла
  серверную проверку для одного доверенного `principal`
- **AND** этот чат точно указан в групповом `telegram.free_response_chats`
- **AND** более ранние запреты не сработали
- **THEN** система вызывает активный `_handle_text_message` без требования
  упоминания или ответа

#### Scenario: Неизвестный чат получает отказ по умолчанию
- **WHEN** Telegram-сообщение приходит из неизвестного, не общего или не
  валидированного чата
- **THEN** система MUST отказать до активной обработки, поиска сессии, памяти,
  инструментов и хода модели

#### Scenario: Другая общая комната остаётся только с упоминанием
- **WHEN** Telegram-сообщение приходит из другой точной общей комнаты, которая не
  указана в `telegram.free_response_chats`
- **AND** сообщение не является триггером упоминания или ответа
- **THEN** система MUST не выполнять активную обработку

#### Scenario: Более ранние запреты остаются главными
- **WHEN** Telegram-сообщение является собственным сообщением, `ignored thread`
  или `disallowed topic`
- **THEN** система MUST отказать до проверки вызова через `free_response`

### Requirement: `free_response` не является полномочием
`telegram.free_response_chats` MUST быть только транспортным триггером для уже
разрешённой области общей комнаты. Он MUST NOT выдавать полномочия
`authorization`, `membership`, `role`, `profile`, `capability` или `delivery`.

#### Scenario: `free_response` не обходит авторизацию `principal`
- **WHEN** отправитель или чат не проходит проверку общей комнаты для одного
  доверенного `principal`
- **AND** `chat ID` присутствует в `telegram.free_response_chats`
- **THEN** система MUST отказать и не считать `free_response` отдельным
  разрешением

#### Scenario: Неавторитетные настройки не создают обход
- **WHEN** `topic-level` `free_response`, `guest mode`, `mention pattern` или
  `require_mention=false` присутствуют без точной серверной проверки общей
  комнаты для одного доверенного `principal`
- **THEN** система MUST не использовать эти значения как обход проверки одного
  доверенного `principal`

#### Scenario: Политики повышенных действий и возможностей не меняются
- **WHEN** активная обработка разрешена через триггер `free_response`
- **THEN** нижележащие `role`, `profile`, `capabilities`, `approval`, `admin` и
  `delivery gates` MUST остаться такими же, как для той же точной области общей
  комнаты через упоминание или ответ

### Requirement: Активное сообщение `free_response` не становится пассивным наблюдением
Сообщение, которое пошло в активную обработку через триггер `free_response`,
MUST NOT сохраняться как пассивное наблюдение того же `Telegram update`.

#### Scenario: Активный `free_response` пропускает запись пассивного наблюдения
- **WHEN** Telegram-сообщение из точной общей комнаты `free_response` вызывает
  `_handle_text_message`
- **THEN** система MUST NOT сохранять то же сообщение как пассивное наблюдение

#### Scenario: Пассивное наблюдение остаётся отдельным для неактивного текста
- **WHEN** текст разрешён для пассивного наблюдения по существующей политике
- **AND** он не был обработан как активный ход через `free_response`
- **THEN** существующее поведение пассивного наблюдения SHALL остаться неизменным

### Requirement: Идентичность темы и нижележащая изоляция сохранены
`free_response`-`hotfix` MUST сохранить существующие `trusted thread identity`,
`session key`, изоляцию памяти и изоляцию доставки для общих тем.

#### Scenario: Две темы сохраняют отдельную идентичность сессии
- **WHEN** две Telegram-темы в одной общей комнате получают текст
- **THEN** система MUST сохранить отдельные `trusted thread identity` и
  `session key` для каждой темы

#### Scenario: `free_response` не добавляет контекст или `schema`
- **WHEN** активная обработка через `free_response` разрешена
- **THEN** система MUST NOT добавлять новые поля контекста, `schema`, `role`,
  `profile`, `tool`, `dependency` или `migration`

#### Scenario: Регрессии упоминания и ответа предотвращены
- **WHEN** точная общая комната получает обычный триггер упоминания или ответа
- **THEN** существующее поведение обработки упоминания/ответа SHALL остаться неизменным
