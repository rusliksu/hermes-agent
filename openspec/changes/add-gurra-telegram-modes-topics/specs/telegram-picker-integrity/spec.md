## ADDED Requirements

### Requirement: Opaque callback state
Каждый Telegram picker MUST использовать непредсказуемый nonce в callback data длиной не более 64 байт, а серверное состояние MUST быть привязано к picker type, message, chat, thread, user, session и expiry.

#### Scenario: Валидный callback
- **WHEN** callback содержит действующий nonce и совпадает со всеми привязанными атрибутами
- **THEN** система применяет ровно выбранное действие

#### Scenario: Подмена контекста
- **WHEN** callback приходит от другого пользователя, чата, топика, сообщения или сессии
- **THEN** система подтверждает callback как недействительный и не изменяет состояние

### Requirement: Срок жизни и одноразовость
Picker state MUST иметь ограниченный TTL, удаляться после успешного выбора и не применяться повторно.

#### Scenario: Просроченный picker
- **WHEN** пользователь нажимает кнопку после expiry
- **THEN** система сообщает, что меню устарело, и не изменяет настройки

#### Scenario: Повторный callback
- **WHEN** успешно использованный nonce поступает повторно
- **THEN** система не выполняет действие второй раз

### Requirement: Конкурентные picker
Система SHALL поддерживать несколько одновременно открытых picker одного пользователя и разные picker в соседних топиках без взаимного перезаписывания.

#### Scenario: Два параллельных меню
- **WHEN** пользователь открывает два picker до выбора в первом
- **THEN** каждое меню сохраняет собственное состояние и применяет только собственный выбор

### Requirement: Быстрое подтверждение callback
Telegram callback MUST быть подтверждён до выполнения потенциально долгого обработчика; ошибки после подтверждения MUST отображаться безопасным редактированием или сообщением.

#### Scenario: Долгое действие
- **WHEN** действие picker требует I/O или запуска runtime-операции
- **THEN** Telegram получает callback acknowledgement до начала долгой части
