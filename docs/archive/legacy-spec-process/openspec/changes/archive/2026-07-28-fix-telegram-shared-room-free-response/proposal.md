## Зачем

Живой Telegram-`hotfix` уже восстановил нужное поведение для общей комнаты с
`telegram.free_response_chats`, но исправление должно стать устойчивым в
`main`, чтобы будущий `deploy` не затёр рабочее состояние.

## Что Меняется

- Закрепить малый отдельный `hotfix`-PR от `main` для
  `plugins/platforms/telegram/adapter.py`: после точной проверки общей комнаты,
  настроенной на сервере для одного доверенного `principal`, точное совпадение
  комнаты в `telegram.free_response_chats` разрешает вызов `_handle_text_message`
  без упоминания или ответа.
- Сохранить отказ по умолчанию (`fail closed`) для неизвестных и не общих
  комнат, а также все более ранние запреты: собственные сообщения,
  игнорируемые темы и запрещённые темы.
- Не записывать то же сообщение как пассивное наблюдение, если оно уже пошло в
  активный вызов `_handle_text_message` через триггер `free_response`.
- Зафиксировать, что `free_response` является только транспортным триггером, а
  не основанием для `authorization`, `membership`, `role`, `profile`,
  `capability` или `delivery`.
- Не добавлять поля контекста, `schema`, `role`, `profile`, `tool`,
  `dependency`, `migration`, абстракции, переделку конфигурации или
  `refactor`.
- Доставить изменение отдельным PR этой задачи; перевод из `draft` в `ready` и
  `merge` выполнять только после реализации, тестов, проверки и строгой
  валидации. Живой `deploy`, `restart`, изменения конфигурации и другие
  `live`-действия не входят в объём этого изменения.

## Возможности

### Новые Возможности

- `telegram-shared-room-free-response`: точный групповой триггер
  `free_response` для уже разрешённых Telegram-общих комнат с одним доверенным
  `principal`, с сохранением границ безопасности, изоляции тем/сессий и
  пассивного наблюдения.

### Изменённые Возможности

Нет.

## Влияние

- Код: только `plugins/platforms/telegram/adapter.py` в существующих ветках
  проверки общей комнаты при реализации после отдельного одобрения.
- Тесты: точечные gateway-тесты вокруг группового допуска,
  `_handle_text_message`, пассивного наблюдения, отказа для неизвестной/другой
  комнаты, запретов для собственных сообщений, игнорируемых и запрещённых тем,
  регрессии упоминания/ответа и изоляции двух тем.
- Без изменений API, `schema`, конфигурации, `dependency`, `migration`,
  `live checkout`, `private config`, сервисов, DB, `deploy`, `restart`, `push`
  или PR на этапе планирования.
- Откат: `revert` `hotfix`-коммита; `live`-откат остаётся отдельным явным
  `live`-шлюзом.
