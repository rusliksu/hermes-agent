## Контекст

TelegramAdapter уже умеет добавлять защищённые inline-кнопки для выбора модели, настроек и остановки операции. Финальные ответы отличаются внутренним `metadata.notify`, а личный Telegram-чат определяется положительным числовым `chat_id`. Slack уже показывает бинарные feedback-кнопки, но его обработчик только журналирует событие и не подходит для четырёх причин Gurra.

Ограничения: prompt cache и сообщения сессии нельзя менять; внешняя телеметрия запрещена без opt-in; callback должен проходить ту же авторизацию и привязку к lane, что остальные Telegram-контролы.

## Цели / Не-цели

**Цели:**

- Добавить opt-in feedback только к финальным ответам в личных чатах Telegram.
- Повторно использовать существующий nonce/state/callback механизм.
- Хранить только минимальное локальное событие без содержимого переписки и сырых идентификаторов.
- Сохранить доставку ответа при любой ошибке feedback-пути.

**Не-цели:**

- Не строить dashboard, Auto-routing или сбор latency в этом change.
- Не добавлять внешний analytics backend.
- Не добавлять кнопки в группы и каналы, где владельца ответа нельзя безопасно вывести из `chat_id`.
- Не менять модель, reasoning, инструменты или системный prompt.

## Решения

1. Использовать `platforms.telegram.extra.feedback_buttons` как явный флаг. Альтернатива — включить всем по умолчанию — отклонена, чтобы не менять UX существующих установок.
2. Добавлять клавиатуру отдельным `edit_message_reply_markup` после успешной доставки или финализации сообщения. Это одинаково работает для legacy Markdown, rich-message и streaming-edit путей и не усложняет каждую отправку параметром `reply_markup`.
3. Привязывать nonce к DM-пользователю (`user_id == chat_id`), чату, топику и message id через существующий `_bound_callback_state`. После первого принятого выбора состояние потребляется, а клавиатура удаляется.
4. Писать событие стандартной библиотекой в профильный `logs/response-feedback.jsonl`: UTC-время, платформа, одна из четырёх категорий и признак топика. Идентификаторы и тексты не записываются.
5. Ошибки добавления клавиатуры и локальной записи только журналируются на debug/warning и не меняют `SendResult`.

## Риски / Компромиссы

- [После перезапуска старые кнопки истекут] → Состояние намеренно остаётся in-memory, как у существующих защищённых Telegram picker-кнопок; пользователь увидит сообщение об истечении.
- [Ограничение 256 состояний может вытеснить старую кнопку] → Feedback рассчитан на быстрый отклик; ограничение защищает память процесса.
- [JSONL не предоставляет dashboard] → Это минимальный сбор сигнала; агрегатор добавляется только после подтверждения пользы.
- [Положительный `chat_id` используется как признак DM] → Это соответствует Telegram Bot API; группы и каналы используют отрицательные идентификаторы.

## План миграции

1. Развернуть код с выключенным флагом — поведение не меняется.
2. Включить `feedback_buttons: true` только у Gurra после отдельного live-gate.
3. Проверить появление кнопок и локальной записи тестовым ответом.
4. Откат: выключить флаг; код и накопленный локальный журнал не влияют на ответы.
